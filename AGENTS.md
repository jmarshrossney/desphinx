# AGENTS.md

Run tasks as `uv run just <task>`: the recipes call tools that are only on the PATH inside the project environment.

## Design constraints

- No runtime dependencies, so the pre-commit hook installs quickly and `uvx` runs it without a project.
  Do not add typer, griffe or anything else to `[project] dependencies`.
- `fix` rewrites only markup with exactly one Markdown equivalent.
  Anything needing a judgement (a fence language, where to move a docstring) is reported, never rewritten.
- The package checks its own `src` and `tests` (`just lint`, and the local pre-commit hook).
  Test inputs containing reST must be runtime strings, never docstrings or comments, or the self-check fails.

## Releasing

Releases are tags on `main`, made by the maintainer; nothing is published to PyPI.

1. `uv version --bump rc` or `--bump stable`, and commit.
2. `just release`.
3. After a stable release, `uv version --bump minor --bump dev` and commit, so a git install of `main` does not report the released version.

## Template

Generated from `python-package-template`; `copier update` pulls in template changes, and `.copier-answers.yml` must not be hand-edited.
Its `_src_path` is relative to the parent directory, so run `copier update desphinx` from there.

This project deliberately diverges from the template, so resolve update conflicts accordingly:

- The marimo example machinery (`examples/`, the marimo dependencies and recipes, the `examples/**` ruff ignores) was removed; the home page example is generated by `just docs-example` instead. Delete it again if an update brings it back.
- `README.md` and `docs/index.md` are this project's own; keep them over the template's install and usage text.

Tool versions are pinned in three places that must stay in step: `[dependency-groups] dev`, the `.pre-commit-config.yaml` revs, and the `uv_build` bound in `[build-system]`.
